# Proposed acceptance gates after M0

Scientist approval is pending. These criteria describe future tests. The M0 images and raw measurements are comparator evidence.

| Gate | Proposed pass condition | Evidence or failure action |
|---|---|---|
| Membership and facets | Exact agreement with supplied group, facet and selected row keys. Input table unchanged. Repeated group labels in two panels produce separate results. Changing an expression colour leaves geometry equal. | Fixtures with reordered factors, nonnumeric IDs, repeated panel labels, missing facet fields and inherited continuous colour. Fail on unintended grouping or recycling. |
| Full envelope | Every selected finite point is inside or on the envelope within a scale-aware floating-point tolerance. Every polygon closes and passes a validity check. One ring per supplied nondegenerate component. | Include duplicates, collinear points, 1/2/3 distinct points, one extreme outlier, rare islands and overlapping labels. For tight bands require two separate component hulls on the unpartitioned PBMC fixture; the manual split is an evaluation reference only. Never claim that a convex hull avoids empty space. |
| Degenerate and incomplete data | Correct type and count for point/segment/area. No silent empty output. Invalid input triggers the declared diagnostic or explicit omission policy with counts. | Include all-identical positions, vertical and diagonal segments, NA/NaN/Inf coordinates and missing group. Check both actual exports and returned geometry. |
| Coordinate and cache stability | Same vertices after row permutation up to canonical ring start/direction. Identical geometry at two device aspect ratios, on resize, Cartesian zoom, equal aspect and flip with inverse coordinate mapping. Precompute and fresh results agree. | Compare numeric output and SVG/PDF device renders. Fail explicitly for unsupported scales, coordinates or incomplete metadata. Changed membership, coordinates, facet keys or computation settings invalidate any cache. |
| Relative performance | Proposed M1 engineering budget is ≤2× the matched base convex reference for geometry + build + draw at 100k points/100 groups, using medians of ≥3 repeated same-machine runs with the same point layer. Peak RSS ≤2× the matching fresh-process reference. | This budget applies only to computing convex hulls with supplied components. Benchmark territory against the pinned CellStyle R reference separately. A regression triggers profiling. Repeat at 10k and 1M before promising scalability. These are proposed overhead ceilings, not achieved product measurements. Record the cost for selected groups and precompute/reuse separately. |
| Visual acceptance | Scientist reviews 2–4 matched variants on the ring, separated islands, outliers, overlapping groups and a representative target embedding at intended print size. Scientist records the acceptable coverage meaning and reasons. | Retain exact figure revisions and decision. Crossing outlines are valid when the supplied labels overlap. Stop if a single default would imply unsupported boundaries or suppress a rare population. |
| Compatibility and release | Test supported ggplot2/R versions and vector/raster exports. Require working examples and R CMD check before release consideration. | No release approval follows from an M0 run. |

For a later representative mode, report empirical coverage, ring/component count, inclusion of a known empty-space probe and sensitivity to 5–10% deterministic thinning. Review sparse groups individually. An HDR mass level alone supplies no empirical-coverage threshold. Performance qualification for density requires a bounded N-by-K grid, peak process memory, vertex counts, resolved grid size and a comparison with native ggdensity. Labels and Python have separate gates.


## Territory and automatic tight-band feasibility

- Replay the two pinned profiles on the full 700-cell fixture. Compare CellStyle territory ring topology and all cell-centre classifications, both for one requested label and all labels. For the proposed tight-band mode require two disjoint valid hulls, 48/48 member centres, zero other centres and agreement with the manual combined area (1.579 rounded, compare full-precision areas at relative tolerance 1e-6). The geometry call cannot receive the manual split or the marker column.
- Exercise abundance imbalance, ties, duplicate multiplicity, unsupported/collinear groups, overlapping clouds, holes and open paths. Check absence of a valid band as a reportable outcome. Test changes to competitors while the selected label stays fixed, label/order stability, facet isolation, and invariance under marker recolouring. Distinguish no coverage from no drawable geometry.
- Compare individual rings by containment and area rather than global path serial numbers. Report disagreements near boundaries separately. Track retained members, other-label inclusions, missing groups, component count and empty-space capture across grid and bandwidth perturbations. Validate parity before optimizing.
- Profile geometry, ggplot build, draw and peak process RSS separately across N and K for one versus all requested labels, including 100k/100 and bounded trials toward 1M/1000. Fix grid width, bandwidth and hardware, then vary grid size independently. No speedup or million-cell acceptance is implied by the upstream examples.

The optional occupied-tile mode has separate tests for overlapping labels, an isolated singleton, component recovery and permutation stability.
